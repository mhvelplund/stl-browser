# Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A toggleable search bar that lists the folders and files below the current folder whose names
match a Free / Word / Regexp query, plus an icon-only Rescan button.

**Architecture:** Matching is a pure function in stl-core over the cached in-memory view tree
(`vtree::search`). A Tauri command `search` wraps it per view, and the Svelte page swaps the tile grid for a
result list while the query is non-empty. Result rows carry their parent path, so the existing `(view, path,
names)` commands (open, drag, extract) work on them unchanged.

**Tech Stack:** Rust (stl-core with the `regex` crate, which is already a dependency; Tauri 2 in
app/src-tauri), Svelte 5 runes and TypeScript, `node --test` for frontend helpers.

**Spec:** `docs/superpowers/specs/2026-10-30-search-design.md`

## Global Constraints

- Rescan glyph: **🗘 (U+1F5D8)**, icon-only, with the same `title` as today and an `aria-label`.
- Modes: `free` (the default), `word`, `regexp`. Case sensitivity is off by default.
- The Aa toggle is shown only in the Files view. The Models view is always case-insensitive.
- Matched text: `Node.label` (case kept) in the Files view, and `Node.name` (lowercase, cleaned) in the
  Models view.
- The scope is fixed when the bar opens. Only the scope's descendants are searched, never the scope itself.
- Result cap: **1000**, with a "showing first 1000" note when it is hit.
- Debounce: **~120 ms**. Stale replies are dropped with a sequence counter.
- Marks are **char** (Unicode scalar) ranges `[start, end)` into the displayed `name`. The frontend splits
  names with `Array.from`.
- Commits use Conventional Commits and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Empty-matching regexps** (`.*`, `a?`, `^`) match every name. They must return hits, with zero-width
   marks dropped, and must stop at the 1000 cap without hanging. Tests in Task 2.
2. **Non-ASCII names** (`Café`, `ÉLF`): case-insensitive matching and highlight ranges must count chars,
   not bytes. Tests in Task 2.
3. **The scope vanishes** after a re-index (the folder was renamed or deleted). The search must fall back to
   the deepest existing folder and report that path, and the bar must show it. Test in Task 3.
4. **A hit's `parent` must round-trip**: `list_folder(view, parent)` must contain the hit by name. This
   covers Models-view hits under synthetic `images` and `docs` nodes, too. Test in Task 3.
5. **Fast typing and re-indexing**: a slow reply for an older query must never overwrite a newer one, and
   `index-done` must re-run an open search. This is enforced by the shared sequence counter in Task 6 and
   checked manually.

### Task 2: The matcher and the tree walk

**Files:**
- Create: `crates/stl-core/src/vtree/search.rs`
- Modify: `crates/stl-core/src/vtree/mod.rs` (add `pub mod search;`)
- Test: `crates/stl-core/tests/vtree_search.rs`

**Interfaces:**
- Consumes: `Node.label` (Task 1), `Tree`, `NodeId`, `Node`, `is_file_kind`.
- Produces:
  ```rust
  pub enum Mode { Free, Word, Regexp }               // derive Debug, Clone, Copy, PartialEq, Eq
  pub enum Field { Name, Label }                     // which node text is matched
  pub struct Matcher { .. }
  impl Matcher {
      pub fn new(query: &str, mode: Mode, case_sensitive: bool) -> Result<Matcher, String>; // Err only for a bad regexp
      pub fn find(&self, text: &str) -> Option<Vec<(usize, usize)>>;                        // char ranges [start, end)
  }
  pub struct Hit { pub id: NodeId, pub parent: Vec<String>, pub marks: Vec<(usize, usize)> }
  pub fn search(t: &Tree, root: NodeId, root_path: &[String], m: &Matcher, field: Field,
                keep: &dyn Fn(&Node) -> bool, limit: usize) -> (Vec<Hit>, bool); // bool = truncated
  ```

Behaviour the tests pin:

- **Word**: the leftmost occurrence of the query as a substring. Its marks are that one range.
- **Free**: each query char matched greedily, leftmost first, in order. Adjacent matched chars merge into
  one range.
- **Case-insensitive Word and Free** compare per char with `a.to_lowercase().eq(b.to_lowercase())`, so char
  indices stay aligned with the original text.
- **Regexp**: `RegexBuilder::new(q).case_insensitive(!case_sensitive).build()`, and the error text is
  returned on failure. Marks are the leftmost match converted from bytes to chars. A zero-width match gives
  `Some(vec![])`.
- **`search`**: depth-first in tree order over `root`'s descendants, excluding `root`. A node failing
  `keep` is skipped along with its subtree. `parent` is `root_path` plus the `name` segments down to the
  hit's parent. After `limit` hits, it stops and returns `true`.
  - With `Field::Label`, marks are kept only if `name.starts_with(&label.to_lowercase())`; otherwise they're
    `vec![]`. Clash suffixes like `_2` (`numbered`) don't break the mapping.

### Task 3: The `search` Tauri command

**Files:**
- Modify: `app/src-tauri/src/browse.rs` (new types and fn next to `list`, tests in its `mod tests`)
- Modify: `app/src-tauri/src/commands.rs` (`search_impl` and `search` after `locate`)

**Interfaces:**
- Consumes: `vtree::search::{Matcher, Mode, Field, search}` (Task 2), plus `visible`, `kind_name` and
  `Views` in browse.rs.
- Produces (serde `camelCase`; `SearchMode` is `rename_all = "lowercase"` and `Deserialize`):
  ```rust
  pub enum SearchMode { Free, Word, Regexp }
  pub struct Hit { name, kind: &'static str, key, real: Vec<String>, file_kind: Option<String>,
                   openable: bool, parent: Vec<String>, marks: Vec<(usize, usize)> }
  pub struct Found { pub path: Vec<String>, pub hits: Vec<Hit>, pub truncated: bool }
  pub const SEARCH_LIMIT: usize = 1000;
  pub fn search(views: &Views, view: View, path: &[String], query: &str, mode: SearchMode,
                case_sensitive: bool) -> Result<Found, String>;
  // commands.rs
  pub fn search_impl(state: &AppState, view: View, path: Vec<String>, query: String, mode: SearchMode,
                     case_sensitive: bool) -> Result<Found, String>;
  #[tauri::command] pub fn search(state, view, path, query, mode, case_sensitive) -> Result<Found, String>;
  ```

Rules: the scope is `t.walk(path)`, and `Found.path = path[..used]`. An empty `query` gives
`Found { hits: [], .. }`. In the Models view, `Field::Name` is used and `case_sensitive` is forced to
`false`. In the Files view, `Field::Label` is used. `keep = visible(view, n)`.
