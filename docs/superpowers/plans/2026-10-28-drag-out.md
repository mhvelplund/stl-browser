# Drag-out (milestone 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drag any tile out of the app into Explorer as Windows virtual files (extracted only when Explorer asks), and
offer a right-click **Extract to…** that writes the same tree.

**Architecture:** A pure *export plan* (`stl-core::vtree::export`) turns the dragged nodes into an ordered list of
folders and files with relative paths that mirror the current view. `stl-index::export` locates each file's source and
chain up front (so entry ids are never trusted later) and writes a plan to disk through a portable
`stl-scan::session::ExtractSession`, which keeps the current stack of open (nested) archives. The Windows-only
`stl-drag` crate wraps a plan in an `IDataObject` (`CFSTR_FILEDESCRIPTORW` + lazy `CFSTR_FILECONTENTS` +
`IDataObjectAsyncCapability`). The object lives in the **MTA** and the main STA thread gets a marshaled proxy for
`DoDragDrop`, so Explorer's calls (and the extraction work) run on COM worker threads, never on the UI thread.

**Tech Stack:** Rust 2024, `windows` 0.62.2 (same as Tauri's), Tauri 2, Svelte 5 + TypeScript.

**Spec:** `docs/superpowers/specs/2026-10-27-stl-browser-design.md` ("Drag-out (Windows virtual files)", milestone 6,
and the manual verification line). Read `docs/index.md` and `CLAUDE.md` too.

## Global Constraints

- `stl-drag` is Windows-only: every item is `#[cfg(windows)]`; the crate builds empty elsewhere.
- Use `windows` / `windows-core` **0.62.2** (already in `Cargo.lock` through Tauri). No other new COM crate.
- Relative paths mirror the **current view's** virtual tree: lowercase display names, `_N` clash names as shown. In the
  Files view only visible items (folders, images, `model`/`scene` files) are included; the Models view includes all.
- Locked (password-protected) items are never opened: they are left out of drags and extractions and counted as skipped.
- Nothing is extracted until asked: the descriptor list costs no archive reads.
- Extraction never trusts an entry id after the plan is made: it carries `(source kind, source path, chain)`.
- The app is Rust + TypeScript only. Shell heredocs mangle backslashes: write files with the editor tools.
- Release keeps `panic = "unwind"`; a panic inside extraction becomes a per-file error, never a crash of the drag.

## Review Focus

1. **Names Windows can't create** (`a:b.stl`, `con.stl`, `name.` , `x?`, a `/` inside a display name): the file is
   written under a sanitized name, never fails the whole drag. → Task 2 `safe_name_*` tests.
2. **A big folder dragged** (thousands of files across many archives, some nested): files from one archive reuse the
   open archive instead of reopening it per file. → Task 3 `session_reuses_open_archives`.
3. **The button is already up when `DoDragDrop` would start** (a quick click-drag-release beats the IPC round trip):
   no drag starts, nothing is dropped on whatever is under the cursor. → Task 5 `button_up_skips_drag` (pure check).
4. **Extract to… into a folder that already has that name**: a new `name (2)` folder, never overwriting. → Task 4
   `unique_dest_*`.
5. **One unreadable file in a drag/extract** (corrupt member, source deleted since indexing): that file fails, the rest
   are written and the failure is reported. → Task 4 `write_tree_continues_after_error`, Task 5 `failed_file_*`.

### Task 2: Export plan (`stl-core`)

**Files:**
- Create: `crates/stl-core/src/vtree/export.rs` (add `pub mod export;` to `vtree/mod.rs`)
- Test: `crates/stl-core/tests/vtree_export.rs`

**Interfaces:**
- Produces:
  - `pub enum ExportKind { Dir, File { entry_id: i64 } }`
  - `pub struct ExportItem { pub rel: String /* '/'-separated, sanitized */, pub kind: ExportKind }`
  - `pub struct ExportPlan { pub items: Vec<ExportItem>, pub skipped: u32 /* locked or no entry */ }`
  - `pub fn export_plan(t: &Tree, roots: &[NodeId], include: &dyn Fn(&Node) -> bool) -> ExportPlan`
  - `pub fn safe_name(name: &str) -> String`

Rules: depth-first in tree order; each folder appears before its contents; a root that is a file gives one item at
the top; folders with no exported content still get a `Dir` item; the tree is a DAG (inner-root volumes share
children), so walk iteratively and don't dedupe across branches. After `safe_name`, two siblings that collide
(case-insensitive) get `_2`, `_3`… before the extension of the later ones. `Locked` nodes and file nodes without
`entry_id` are counted in `skipped`. `include` is applied to every node below the roots (the roots are always taken).

`safe_name`: replace `< > : " / \ | ? *` and chars < 0x20 by `_`; trim trailing `.` and spaces; empty becomes `_`; a
stem equal to a DOS device name (`con prn aux nul com1-9 lpt1-9`, any case, with or without extension) gets a leading
`_`.

- [ ] **Step 1: Write the failing tests** in `crates/stl-core/tests/vtree_export.rs`, building small trees with
  `Tree::add` and setting `info.entry_id`:
  - `plan_mirrors_tree`: root folder `orc` with `images/orc.jpg` (id 1), `orc.stl` (id 2), empty folder `docs` →
    rels `["orc", "orc/images", "orc/images/orc.jpg", "orc/orc.stl", "orc/docs"]` in tree order with matching kinds.
  - `plan_of_a_file_root`: roots = `[file node]` → one `File` item `elf.stl`.
  - `plan_skips_locked_and_filtered`: a `Locked` child and a child rejected by `include` are absent; `skipped == 1`
    (only the locked one counts).
  - `plan_two_roots`: roots `[a, b]` → both subtrees, `a` first.
  - `safe_name_replaces_reserved_chars`: `"a:b?.stl"` → `"a_b_.stl"`, `"x/y"` → `"x_y"`, `"tab\there"` → `"tab_here"`.
  - `safe_name_trims_and_guards_devices`: `"name. "` → `"name"`, `"..."` → `"_"`, `"con.stl"` → `"_con.stl"`,
    `"COM1"` → `"_COM1"`, `"console.stl"` unchanged.
  - `plan_renames_sanitized_clashes`: siblings `a?.stl` and `a_.stl` → `a_.stl`, `a__2.stl`.

### Task 3: Extraction session (`stl-scan`)

**Files:**
- Create: `crates/stl-scan/src/session.rs` (add `pub mod session;` to `lib.rs`)
- Modify: `crates/stl-scan/src/nested.rs` only if a counter is needed for the test (see below)
- Test: `crates/stl-scan/tests/session.rs` (reuse the fixture helpers the `nested`/`extract` tests use)

**Interfaces:**
- Consumes: `archive::open`, `nested::open_member`, `extract::SourceKind`.
- Produces:
  - `pub struct ExtractSession` (holds the open stack for one source: `source_path`, then one
    `(member, Box<dyn Archive>, Option<TempPath>)` per nested level). `Send`.
  - `impl ExtractSession { pub fn new() -> Self; pub fn extract(&mut self, kind: SourceKind, source_path: &Path,
    chain: &[String], out: &mut dyn Write) -> Result<u64, ScanError>; pub fn opens(&self) -> usize }`
  - `opens()` counts archive opens (outer + nested) done by this session, for tests.

Behaviour: same result as `extract_entry`. The open stack is reused while the next file's source and chain prefix
match; on a mismatch it is truncated to the common prefix and reopened from there. Folder sources bypass the stack. A
failed extraction drops the stack (an archive reader may be left mid-stream). A panic inside a reader is caught by the
caller (Task 4/5), not here.

### Task 4: Locate entries and write a plan to disk (`stl-index`)

**Files:**
- Create: `crates/stl-index/src/export.rs` (add to `lib.rs`)
- Test: `crates/stl-index/tests/export.rs`

**Interfaces:**
- Consumes: `ExportPlan`, `ExportItem`, `ExportKind` (Task 2); `ExtractSession` (Task 3).
- Produces:
  - `pub struct EntryLoc { pub kind: SourceKind, pub source_path: String, pub chain: Vec<String>, pub size: Option<u64> }`
  - `pub fn locate(conn: &Connection, ids: &[i64]) -> Result<HashMap<i64, EntryLoc>, IndexError>` (unknown ids are
    absent)
  - `pub struct ExportFile { pub rel: String, pub is_dir: bool, pub loc: Option<EntryLoc> }` and
    `pub fn resolve_plan(conn: &Connection, plan: &ExportPlan) -> Result<Vec<ExportFile>, IndexError>` — every plan
    item in order; `loc` is `None` for a dir, and for a file whose entry vanished (the writer reports it as failed).
  - `pub fn unique_dest(dir: &Path, name: &str) -> PathBuf` — `dir/name`, else `dir/name (2)`, `(3)`…
    (before the extension for a file name).
  - `pub struct WriteReport { pub files: u32, pub dirs: u32, pub failed: Vec<(String, String)> /* rel, error */, pub bytes: u64 }`
  - `pub fn write_tree(dest: &Path, files: &[ExportFile], session: &mut ExtractSession,
    progress: &mut dyn FnMut(usize, &str), cancel: &AtomicBool) -> WriteReport`

`write_tree` writes the plan's top-level names as given (the caller picked `dest` and made top names unique with
`unique_dest` beforehand — see Task 6); it creates parent dirs as needed, writes each file through the session into a
`<name>.part` file renamed on success (a failure removes the part file), catches panics per file
(`catch_unwind(AssertUnwindSafe)`; after a panic replace the session with a fresh one), and stops early when `cancel`
is set. `progress(index, rel)` is called before each item.

### Task 5: `stl-drag` crate (Windows OLE virtual-file drag)

**Files:**
- Create: `crates/stl-drag/Cargo.toml`, `src/lib.rs` (public API), `src/data.rs` (the `IDataObject` +
  `IDataObjectAsyncCapability` + `IEnumFORMATETC` via `SHCreateStdEnumFmtEtc`), `src/stream.rs` (`IStream` over a
  delete-on-close temp file), `src/source.rs` (`IDropSource`)
- Test: `crates/stl-drag/tests/drop.rs` (the spike's drop-target test, promoted) and unit tests in `src/`

**Interfaces:**
- Produces (all `#[cfg(windows)]`):
  - `pub struct Descriptor { pub rel: String /* '\\'-separated */, pub is_dir: bool, pub size: Option<u64> }`
  - `pub trait Contents: Send + Sync + 'static { fn write(&self, index: usize, out: &mut dyn std::io::Write) -> Result<(), String>; }`
    (`index` = descriptor index; called on COM worker threads, possibly concurrently)
  - `pub struct Prepared` (`Send`): a marshaled `IDataObject` waiting for the STA.
  - `pub fn prepare(items: Vec<Descriptor>, contents: Arc<dyn Contents>) -> Result<Prepared, String>` — call on any
    non-STA thread; creates the object in the MTA (kept alive once per process by `CoIncrementMTAUsage`).
  - `impl Prepared { pub fn data_object(self) -> windows::core::Result<IDataObject> /* unmarshal on the current thread */ }`
  - `pub fn run_drag(p: Prepared) -> Result<DragOutcome, String>` — on the OLE STA (Tauri's main thread): skip if the
    primary button is no longer down, else `DoDragDrop(proxy, source, DROPEFFECT_COPY)`.
  - `pub enum DragOutcome { Skipped, Dropped, Cancelled }`
  - `pub fn primary_button_down(swapped: bool, left: bool, right: bool) -> bool` (pure; `run_drag` feeds it
    `GetSystemMetrics(SM_SWAPBUTTON)` and `GetAsyncKeyState`)

Data object behaviour: formats offered by `EnumFormatEtc`/`QueryGetData`: `CFSTR_FILEDESCRIPTORW` (TYMED_HGLOBAL) and
`CFSTR_FILECONTENTS` (TYMED_ISTREAM, any `lindex`), plus `CFSTR_PREFERREDDROPEFFECT` = `DROPEFFECT_COPY`. Each
descriptor sets `FD_ATTRIBUTES | FD_PROGRESSUI` (+ `FD_FILESIZE` when the size is known), `FILE_ATTRIBUTE_DIRECTORY`
for dirs, and the `\`-separated relative path in `cFileName` (max 259 chars: longer paths are a failed file, reported
by Explorer). `GetData(FILECONTENTS, i)` calls `contents.write(i, temp file)`, rewinds and returns the `IStream`;
`Err` → `E_FAIL`. `SetData` returns `E_NOTIMPL`. Async: `GetAsyncMode` → TRUE; `StartOperation`/`InOperation`/
`EndOperation` keep a flag. All state behind `Mutex`/atomics (MTA object).
