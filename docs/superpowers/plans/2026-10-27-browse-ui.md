# Browse UI (milestone 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browse the index in the app: add a folder, rescan with progress, and walk the Models and Files views in a
virtualized grid of large tiles with breadcrumbs, padlock items and real-path tooltips.

**Architecture:** Both view trees are built once from the DB and cached in `AppState` (`Arc<Views>` plus per-node
counts), rebuilt by the index worker after each run and swapped in. Indexing runs on its own thread with its own SQLite
connection (WAL), so browsing keeps working from the cache; it reports through `index-progress` / `index-done` events.
`list_folder(view, path)` takes the path as name segments and returns the deepest folder that still exists. The UI is
one Svelte page with small components, and its logic (grid math, navigation history, tile subtitles) sits in pure
TypeScript modules tested with `node --test`.

**Tech Stack:** Rust (Tauri 2, rusqlite, serde), Svelte 5 runes + TypeScript, `@tauri-apps/plugin-dialog`, Node 24
built-in test runner (type stripping, no new npm deps).

**Spec:** `docs/superpowers/specs/2026-10-27-stl-browser-design.md` (Browsing, Indexing, UI), with
`docs/virtual-tree.md` (views, naming, hover) and the approved mockup
<https://claude.ai/artifact/Vum7b4yY5TjCBW1Csez2BH> (`project/Main.dc.html`).

## Global Constraints

- Commands: add folder via the dialog plugin, rescan with `index-progress` events, `list_folder(view, path)`.
- Toolbar: Back / Up / breadcrumb · Models | Files toggle · **Add folder** · **Rescan all** (with a progress bar).
- Main area: a virtualized grid of large tiles (~200px min width, square art area, name below, item count).
  Double-click opens. Status bar: index stats (and later the thumbnail queue). Light/dark follows the OS.
- Names shown are the tree's lowercase names; hover (`title`) shows `real` paths, one per line.
- Password-protected items show a box-with-padlock icon and cannot be opened.
- Files view shows subfolders, images and object files (`file_kind` `model`, `scene`, `image`); other files are
  hidden. The Models view shows everything the resolver put in the tree (its `docs` folder is deliberate).
- A root folder that no longer exists is flagged in the UI, not deleted.
- Indexing runs in the background; the UI stays usable. Only one index run at a time.
- No thumbnails (milestone 5), no drag-out or Extract to… (milestone 6): no buttons for them either.
- No network at runtime: no Google Fonts; use `"IBM Plex Sans", "Segoe UI", system-ui, sans-serif`.
- Mockup palette (dark): bg `#15171A`, bars `#1B1E22`, border `#2C3137`, control `#22262B`/`#343A42`, text
  `#E8EAED`, muted `#9AA1AB`, accent `#5CC8D6` (on-accent `#0E2226`), selected tile `#1C2A2D`/`#3E8F99`. Define them as
  CSS custom properties with a light-scheme override under `@media (prefers-color-scheme: light)`.
- Tests: `cargo test --workspace` and `npm --prefix app test` and `npm --prefix app run check` must pass at every commit.

## Review Focus

1. **The open folder vanishes after a rescan** (archive deleted/renamed): `list_folder` returns the deepest ancestor
   that still exists, with its real `path`, and the UI moves there instead of erroring. → Task 2 test
   `list_falls_back_to_deepest_existing_folder`.
2. **A name containing `/`** (or a path ending on a file): segments are matched whole, never re-split, and a path
   ending on a leaf lists the leaf's folder. → Task 1 test `walk_matches_whole_segments`, Task 2 test
   `list_on_a_file_lists_its_folder`.
3. **Rescan or Add folder pressed while an index runs** (or the run errors/panics): the second run is refused with a
   message, and the busy flag is always released. → Task 3 tests `second_index_is_refused`,
   `busy_flag_released_on_drop`.
4. **Empty library** (first launch, no roots): `list_folder` of the root returns no items and `status` no roots; the
   UI shows an empty state with Add folder. → Task 2 test `empty_db_lists_nothing`.
5. **A root folder is missing** (drive unplugged): `status` marks it `missing`, the run reports a warning, and its
   items stay browsable. → Task 3 test `status_flags_missing_root`.

Also pinned: inner-root volumes share nodes, so counts must not double-walk or loop (Task 1
`counts_with_shared_children`); 3,000 items (Necrossia) render a bounded number of tiles (Task 4
`visible_rows_bounded`).

### Task 1: Tree walk by segments and per-node counts (stl-core)

**Files:**
- Modify: `crates/stl-core/src/vtree/mod.rs` (add `walk`, `Counts`, `counts`; unit tests in its `tests` module)

**Interfaces:**
- Produces:
  - `impl Tree { pub fn walk<S: AsRef<str>>(&self, parts: &[S]) -> (NodeId, usize) }`: follows segments
    case-insensitively (each segment lowercased, compared whole with the child's name), stops at the first segment
    that has no matching child **or** whose match is a leaf (`is_file_kind`); returns the last folder reached and how
    many segments were consumed.
  - `#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)] pub struct Counts { pub models: u32, pub files: u32, pub images: u32 }`
  - `pub fn counts(t: &Tree) -> Vec<Counts>`: one per node, the totals of everything below it (the node itself
    included for leaves). `models` counts `NodeKind::Model` nodes; `files` counts `File` nodes whose `file_kind` is
    `model` or `scene`; `images` counts `Image` nodes and `File` nodes with `file_kind == "image"`. Computed once,
    post-order with a memo (the tree is a DAG: inner-root volumes share children), iterative, no recursion.

#[test]
fn walk_matches_whole_segments() {
    let mut t = Tree::new();
    let v = t.add(0, "Vol", NodeKind::Volume);
    let odd = t.add(v, "a/b", NodeKind::Folder);
    let f = t.add(odd, "x.stl", NodeKind::File);
    assert_eq!(t.walk(&["VOL", "a/b"]), (odd, 2));
    assert_eq!(t.walk(&["vol", "a", "b"]), (v, 1));
    assert_eq!(t.walk(&["vol", "a/b", "x.stl"]), (odd, 2)); // a leaf is never the folder
    assert_eq!(t.walk::<&str>(&[]), (0, 0));
    let _ = f;
}

#[test]
fn counts_sum_below() {
    let mut t = Tree::new();
    let c = t.add(0, "c", NodeKind::Collection);
    let m = t.add(c, "m", NodeKind::Model);
    let imgs = t.add(m, "images", NodeKind::Images);
    t.add(imgs, "a.jpg", NodeKind::Image);
    for (n, k) in [("a.stl", "model"), ("a.lys", "scene"), ("a.mtl", "companion"), ("p.png", "image")] {
        let id = t.add(m, n, NodeKind::File);
        t.nodes[id].info.file_kind = Some(k.into());
    }
    let cs = counts(&t);
    assert_eq!(cs[c], Counts { models: 1, files: 2, images: 2 });
    assert_eq!(cs[imgs], Counts { models: 0, files: 0, images: 1 });
}

#[test]
fn counts_with_shared_children() {
    let mut t = Tree::new();
    let outer = t.add(0, "outer", NodeKind::Volume);
    let m = t.add(outer, "m", NodeKind::Model);
    let inner = t.add(0, "inner", NodeKind::Volume);
    t.nodes[inner].children = vec![m];
    let cs = counts(&t);
    assert_eq!(cs[outer].models, 1);
    assert_eq!(cs[inner].models, 1);
}

### Task 3: Background indexing, add folder, status (app crate)

**Files:**
- Create: `app/src-tauri/src/indexer.rs`
- Modify: `app/src-tauri/src/state.rs`, `app/src-tauri/src/commands.rs`, `app/src-tauri/src/lib.rs`

**Interfaces:**
- Consumes: `build_views`, `AppState::set_views` (Task 2); `stl_index::scanstore::{add_root, Progress}`,
  `stl_index::resolvestore::index_all`, `stl_scan::nested::ListOptions`.
- Produces:
  - Event payloads, `#[derive(Serialize, Clone)] #[serde(rename_all = "camelCase")]`:
    - `IndexProgress { index: usize, total: usize, name: String }`, emitted as `"index-progress"` (`index` is
      1-based for display).
    - `IndexDone { ok: bool, error: Option<String>, sources: usize, listed: usize, removed: usize, errors: usize, locked: usize, resolved: usize, models: usize, warnings: Vec<String>, seconds: f64 }`,
      emitted as `"index-done"` exactly once per run, after the new views are in place.
  - `pub fn run_index(db_path: &Path, progress: &mut dyn FnMut(IndexProgress)) -> (IndexDone, Option<Views>)`:
    opens its own connection with `stl_index::db::open`, runs `index_all` with `ListOptions::default()`, collects
    `Progress::Warning` into `warnings`, then `build_views` on the same connection. Any error becomes
    `ok: false, error: Some(..)` and `None` views. Never panics outward (wrap the body in `catch_unwind`; a panic
    becomes `error: Some("internal error: …")`).
  - `AppState` gains `indexing: AtomicBool` and `pub fn try_begin_index(&self) -> Option<IndexGuard<'_>>`;
    `IndexGuard` clears the flag on `Drop`. `pub fn is_indexing(&self) -> bool`.
  - `pub fn start_index(app: tauri::AppHandle) -> Result<(), String>`: takes the guard from
    `app.state::<AppState>()` or returns `Err("an index run is already in progress")`; spawns a thread that moves the
    guard in (use an owned flag handle: make `indexing` an `Arc<AtomicBool>` and `IndexGuard` own a clone, so the
    guard is `'static`), runs `run_index` emitting progress, calls `set_views` on success, then emits `index-done`.
  - Commands:
    - `rescan(app) -> Result<(), String>` = `start_index`.
    - `add_folder(app, path: String) -> Result<RootInfo, String>`: refuses while indexing (same message), else
      `add_root` on `state.db`, then `start_index`.
    - `status(state) -> Result<Status, String>`.
  - `Status { roots: Vec<RootInfo>, models: i64, files: i64, indexing: bool }` and
    `RootInfo { id: i64, name: String, path: String, missing: bool }` (camelCase). `files` = count of `entries`.
    `missing` = `!Path::new(&path).is_dir()`. `pub fn status_impl(state: &AppState) -> Result<Status, String>`.

    - other folders: Models view `"<models> models · <images> images"` when `models > 0`, else
      `"<children> items · <files> files"`; Files view always `"<children> items · <files> files"`.
    - Singulars: `1 model`, `1 image`, `1 file`, `1 item`.
    - `folderSummary`: Models view `"<models> models · <images> images · <files> files"`; Files view
      `"<items.length> items · <files> files"`.
