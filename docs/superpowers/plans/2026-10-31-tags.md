# Tags (milestone 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** User tags and generated metadata tags on files and folders: stored in the index DB, shown as coloured dots
with a pill popover, edited in a side panel, and searchable with `tag:` terms.

**Architecture:**
- **`stl-core::vtree::tags`** holds the pure tag model: kinds, normalising, real-path tag keys, variant atoms, the
  exclusivity rule, query parsing and effective tags.
- **Generated tags live in `Info.tags`** on the cached trees. They are built by `build_models` and copied into the
  Files tree by real path.
- **User tags and hides** live in three v6 tables. `stl-index::tagstore` reads and writes them, and they are loaded per
  command, the way `selected_thumb` is.
- **Search** gains a tag filter that carries inherited tags down the walk.

**Tech Stack:** Rust (rusqlite, serde), Tauri 2 commands, Svelte 5 + TypeScript, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-31-tags-design.md`

## Global Constraints

- **Kinds and colours:**
  - `user`: green
  - `support`: yellow
  - `scale`: blue
  - `creator`: red
  - `edition`: purple
- **Settable kinds:** only `user`, `support`, `scale` and `creator` can be set by the user. `edition` is generated only,
  and it can be hidden.
- **Dot order:** user, support, scale, creator, edition.
- **Tag key:** `r:` + the real path, lowercased, with `/` turned into `\` and a trailing `\` trimmed. Write the tag under
  every one of the node's `real` paths, and read the union.
- **Normalised tag name:** trimmed, lowercased, runs of whitespace turned into one space. An empty name is refused.
- **Supported and unsupported exclude each other:** an item that would get both gets neither. More than one distinct
  scale on one item gives no scale tag. `lychee` and `chitubox` never conflict.
- **A user-set support, scale or creator value** replaces the generated tags of that kind:
  - on the item itself;
  - in search, for everything below it.
  - At most one user-set value per kind per item: setting a new one replaces the old.
- **Only the item's own tags** show as dots and pills. Inherited tags count in search only.
- **A tag-only search returns the topmost passing nodes** and doesn't descend below a hit. Search never returns the
  scope folder itself.
- **Schema changes go through `MIGRATIONS`:** bump `SCHEMA_VERSION` to 6 and update `crates/stl-index/tests/db.rs`.
- **Commits:** only `feat`/`fix`/`chore(scope)`, each with the attribution lines. No version bumps, no `CHANGELOG.md`
  edits.
- **Test names** must be invented (no real collection, studio or product names). Write source files with the editor
  tools, not heredocs.

## Review Focus

1. **Odd `tag:` input:**
   - `tag:` with nothing after it is ignored.
   - An unterminated `tag:"robot legion` takes the rest of the string.
   - `TAG:Tinmen` works, because the prefix is case-insensitive.

   Tested in Task 1 (`parse_query_edge_cases`).
2. **Merged folders and differing path forms.** The same thing has `/` vs `\` and differing case in its real paths
   across the views, and a merged folder has several real paths. A tag added in one view must show in the other, and
   removing it must clear every key. Tested in Task 5 (`tag_shows_in_both_views`, `remove_clears_every_real_path`).
3. **A tag-only search on a big tagged folder** must return the folder alone, not its 1000 descendants. Tested in
   Task 4 (`tag_only_search_stops_at_topmost`).
4. **Removing a user-set override** brings the generated value back, and setting a second value of a kind replaces the
   first. Tested in Task 3 (`setting_a_kind_replaces_the_old_value`) and Task 1 (`override_and_restore`).
5. **Searching inside a folder that already has the tag** returns its direct children. Tested in Task 4
   (`scope_inside_tagged_folder_lists_children`).

  ```rust
  pub enum TagKind { User, Support, Scale, Creator, Edition }   // Ord = dot order
  impl TagKind {
      pub fn as_str(self) -> &'static str;          // "user" | "support" | "scale" | "creator" | "edition"
      pub fn parse(s: &str) -> Option<TagKind>;
      pub fn settable(self) -> bool;                // false only for Edition
  }
  #[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
  pub struct Tag { pub kind: TagKind, pub name: String, pub by_user: bool }
  pub fn normalize(name: &str) -> Option<String>;
  pub fn tag_key(real: &str) -> String;
  pub fn tag_keys(n: &Node) -> Vec<String>;         // one per real path, deduped
  pub fn variant_tags(label: &str) -> Vec<Tag>;     // "supported+25mm" -> support supported, scale 25mm
  pub fn exclusive(tags: Vec<Tag>) -> Vec<Tag>;     // the exclusivity rule, sorted + deduped
  pub struct ParsedQuery { pub text: String, pub tags: Vec<String> }
  pub fn parse_query(q: &str) -> ParsedQuery;
  #[derive(Debug, Clone, Default)]
  pub struct UserTags {
      pub set: HashMap<String, Vec<Tag>>,                 // tag key -> user-set tags (by_user = true)
      pub hidden: HashMap<String, Vec<(TagKind, String)>>,
  }
  impl UserTags {
      pub fn effective(&self, n: &Node) -> Vec<Tag>;      // own tags, sorted by (kind, name)
      pub fn hidden_of(&self, n: &Node) -> Vec<Tag>;      // generated tags of n that are hidden
  }
  ```

### Task 4: Tag terms in search (`stl-core`)

**Files:**

  test file; find it with `grep -l "Matcher::new" crates/stl-core/tests`).

**Interfaces:**
- Consumes: `Tag`, `TagKind` (Task 1).
- Produces:
  ```rust
  #[derive(Debug, Clone, Default)]
  pub struct Inherited { names: HashSet<String>, overridden: HashSet<TagKind> }
  impl Inherited {
      /// What a child of a node with these own (effective) tags inherits.
      pub fn push(&self, own: &[Tag]) -> Inherited;
      /// Whether `own` plus what was inherited covers every term.
      pub fn covers(&self, own: &[Tag], terms: &[String]) -> bool;
      /// Inherited set at the folder `path` (the root to that folder, the folder's own tags included).
      pub fn along(t: &Tree, path: &[String], own: &dyn Fn(NodeId) -> Vec<Tag>) -> Inherited;
  }
  pub struct TagFilter<'a> { pub terms: &'a [String], pub own: &'a dyn Fn(NodeId) -> Vec<Tag>, pub start: Inherited }
  pub fn search(t: &Tree, root: NodeId, root_path: &[String], m: Option<&Matcher>, field: Field,
                keep: &dyn Fn(&Node) -> bool, tags: &TagFilter, limit: usize) -> (Vec<Hit>, bool);
  ```
- **The rules:**
  - `push` adds the name of every own tag, except generated tags whose kind is in `overridden`. It then adds to
    `overridden` the kinds of own `by_user` tags that aren't `User`.
  - `covers` uses the same filter for `own`.
  - With `m == None` and terms present: a node that passes is a hit, and the walk doesn't descend into it. A node that
    doesn't pass is descended into.
  - With `m == Some`: a hit needs a name match and `covers`, and the walk always descends.
  - With `m == None` and no terms: no hits.
