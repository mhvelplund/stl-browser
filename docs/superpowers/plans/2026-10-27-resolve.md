# Resolve (Milestone 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the prototype's model resolver and virtual tree to Rust, store resolved tables per collection, build
the Models and Files views with the lowercase/merge/`_N`/hover/padlock naming rules, and prove parity with the
prototype on the real Vol.1 + Vol.2 data.

**Architecture:** `stl-core` gets the pure logic: the rest of `names.py`, a `resolve` module (physical tree → logical
tree → model detection → asset attachment → unit collapse) and a `vtree` module (one arena tree type, the naming
rules, the Models and Files view builders fed by plain row structs). `stl-index` gets schema v4 (resolved tables),
`resolvestore.rs` (collection entries → `resolve` → rows, re-run for changed collections), `views.rs` (DB rows → view
builders, inner-root volumes) and new `stlx` commands (`index`, `tree`, `parity`).

**Tech Stack:** Rust 2024, `regex` (no lookaround: see constraints), `indexmap` (new, in `stl-core`), `serde_json`,
rusqlite.

**Spec:** `docs/superpowers/specs/2026-10-27-stl-browser-design.md`. Binding detail: `docs/archive-patterns.md` (the
resolver, parity baseline, spot checks) and `docs/virtual-tree.md` (tables, both views, naming rules). The algorithm
reference is `prototype/stlindex/{names,resolve,vtree,db,cli}.py`; "port X" in a step means a faithful port of that
Python function, same branches and same order.

## Global Constraints

- `stl-core` does no I/O. No Python, 7-Zip or external tool at runtime; nothing in `prototype/` is built.
- **Python → Rust fidelity** (the 47 ported tests depend on these):
  - Python `len`, indexing and slicing on `str` count **chars**, not bytes (`03. ОРКИ`, Cyrillic member names). Use
    `chars().count()` and char-boundary slicing. `regex` match offsets are bytes; `_unsquash_prefix` must map a byte
    offset in the squashed string back to `n`.
  - Python `dict` keeps insertion order. `PDir.children` / `LNode.children` use `IndexMap`; `walk` is pre-order in
    insertion order. Group and model creation order must match the prototype.
  - Python `sorted`/`sort` are stable; `sort(..., reverse=True)` keeps equal items in original order. Use stable sorts
    with reversed comparators, never `sort_unstable`.
  - `str.isdigit()` → `!s.is_empty() && s.chars().all(|c| c.is_ascii_digit())` (`is_digits` helper in `names.rs`).
  - `regex` has no lookahead: `_CATALOG` becomes `^\s*(\d{3,4})(?:\s*-\s*\d{3,4})?[\s_\-.]+` (equivalent: the
    lookahead char is consumed by the following `[\s_\-.]*`). `fullmatch` → anchor with `^(?:…)$`.
  - `Counter.most_common(1)` ties go to the first inserted key.
- Resolution unit: one **(root_id, collection)**. Resolved tables (`groups`, `models`, `model_files`, `assets`) are
  deleted and re-inserted per unit and never hold user data.
- Display names in both views are **lowercase**; real paths keep their case.
- Clash postfix: `_1`, `_2`… in order of first real path, before the extension for files (`orc_1.stl`), at the end
  for folders. All members of a clash get a number.
- Hover (real) path: Windows separators up to the first archive, `/` inside archives, `!` at each archive boundary:
  `D:\STL\Vol.1\01. Studio Collection\Ghamak.rar!Ghamak/842_Tarantula.zip!842_Tarantula_Supported/body.stl`.
- User-data keys: Models view `m:<collection>/<path>`; Files view `f:<source path>|<inner path>`. Never row ids.
- Schema changes go through `MIGRATIONS` in `crates/stl-index/src/db.rs` (bump `SCHEMA_VERSION`, update
  `tests/db.rs`).
- Tests and `stlx` runs use `STL_BROWSER_HOME=<scratch dir>`; the prototype DB is opened **read-only**, never with
  `db::open` (that would migrate it).

## Review Focus

1. **A collection whose root resolves to a single model** (e.g. a lone `Socratus_Typho.rar` as the whole collection)
   has no root group. The prototype's `vtree.build` would crash (`gnode[None]`). The model must appear directly in its
   collection folder. *Test in Task 6.*
2. **Two roots where one contains the other** (`D:\STL` and `D:\STL\Vol.1`): each source is stored once, under the
   outer root; rescanning the inner root must not steal or delete the outer root's sources; the inner volume shows the
   same content. *Tests in Task 4 and Task 8.*
3. **Cyrillic and other multi-byte names** in the resolver (`03. ОРКИ`, `_display_prefix`, `sidecar_key` length
   checks) must not panic on char boundaries. *Test in Task 3.*
4. **Archives with the same stem in one folder** (`X.zip` + `x.rar`) or a folder and an archive of the same name: both
   show as `x`; they must not merge, they get `x_1` / `x_2`. Case-variant folders inside one archive (`Foo/`, `foo/`)
   do merge. *Test in Task 7.*
5. **A rescan with no changes** must not re-resolve anything, and removing the last source of a collection must remove
   its resolved rows. *Test in Task 4.*

```rust
pub type NodeId = usize;
pub enum NodeKind { Root, Volume, Collection, Group, Model, Images, Docs, Variant, Part, Folder, Archive, File, Image, Locked }
pub struct Node { pub name: String, pub kind: NodeKind, pub children: Vec<NodeId>, pub real: Vec<String>,
                  pub key: String, pub info: Info }
#[derive(Default)] pub struct Info { pub entry_id: Option<i64>, pub file_kind: Option<String>, pub model_id: Option<i64>,
    pub group_id: Option<i64>, pub asset_id: Option<i64>, pub hero_asset_id: Option<i64>, pub poster_asset_id: Option<i64>,

    pub raw_name: Option<String>, pub role: Option<String>, pub badge: Option<String> }
pub struct Tree { pub nodes: Vec<Node> }   // nodes[0] is the Root
impl Tree {
    pub fn new() -> Self;
    pub fn add(&mut self, parent: NodeId, name: &str, kind: NodeKind) -> NodeId;   // stores name lowercased
    pub fn find(&self, path: &str) -> Option<NodeId>;   // '/'-separated, case-insensitive, from the root
    pub fn finish(&mut self, alt: &dyn Fn(&Node) -> Option<String>);   // naming rules + sort, whole tree
}
pub fn archive_real(source_path: &str, chain: &[String]) -> String;   // "D:\x\a.zip!dir/b.zip!c.stl"
pub fn folder_real(source_path: &str, rel: &str) -> String;           // "D:\x\Coll" + "sub/a.stl" → "D:\x\Coll\sub\a.stl"
pub fn parent_real(path: &str) -> &str;        // strip the last component ("\", "/" or "!" boundary)
pub fn common_real(paths: &[&str]) -> String;  // longest common prefix at component boundaries
pub fn is_file_kind(kind: NodeKind) -> bool;   // File, Image, Locked
```

`finish` per node, children first lowercased already: (1) group children by name; (2) for a clash containing a
`Model`, apply `alt` to every clashing model (`name (alt)`, alt lowercased); (3) any names still clashing get `_1…_n`
in order of `real[0]` (then insertion order), before the extension for `is_file_kind` nodes (`orc_1.stl`), at the end
otherwise; (4) sort: `Images`, `Docs`, then non-file kinds, then file kinds, each by name. Merging is done by the
builders (Tasks 6–7), not by `finish`.
